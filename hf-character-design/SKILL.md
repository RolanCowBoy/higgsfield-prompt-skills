# Higgsfield character design

Read [the shared contract](references/prompt-core.md). Consult [design examples](references/design-patterns.md) for silhouette-led descriptions and controlled alternatives.

## Choose the design operation
Distinguish creating a new character, exploring alternatives, deliberately redesigning an existing one, and preserving an approved design. For a minor requested change, follow an edit boundary rather than generating an unrelated replacement. A character sheet is a consistency task after design approval; do not introduce multiple new faces while making its views.

Extract the role, intended medium, apparent age if supplied, cultural/time setting if relevant, appeal, distinguishing features, and required framing. Do not invent demographics or background details to fill a template. Resolve only missing decisions that materially affect the design.

## Build a compact visual hierarchy
1. State the broad silhouette and dominant proportion relationship.
2. Select a few identity anchors: head shape, eye spacing, hair mass, distinctive teeth or accessory, body balance. Keep recognizability in large shapes.
3. Describe face, hair, clothing layers, and material only to the requested degree. Separate hair mass, curl pattern, forehead exposure, and color; “messy” alone does not specify these.
4. Translate personality into a readable pose or one behavior cue. A still image depicts a selected instant, not a timed sequence.
5. Specify view, crop, spatial margins, background, and light that reveal the design. Neutral backgrounds and even light are useful for a reusable asset but are not mandatory for narrative illustrations.
6. Describe the actual medium using visible features, rather than piling together incompatible style names.

Keep intentional grotesque proportions while ensuring the body supports the head and feet fit the design. Exaggeration need not make every feature larger. If the user wants visible brows, explicitly separate the forehead opening from the overall hair volume.

Preserve the functional identity of requested props, not just their material or appearance. A hand puppet needs a hand opening and a plausible wearable construction; a generic rag doll is not an equivalent. Describe the hand/prop relationship when it identifies the object or the character's action.

## Explore without losing control
When variations are requested, vary a meaningful axis such as head/body ratio, silhouette rhythm, or costume shape. State what stays common. Respect the requested number of alternatives; do not generate unsolicited grids or spend generation credits for a prompt-only request.
When one version is chosen, produce a brief approved-design description and reference role for future work. Treat rejected variants as rejected rather than mixing their features back in.

For a group, distinguish silhouette, age if specified, clothing, pose, and placement. Check overlap and count. If exact identity/count is essential, suggest separate assets and assembly as an option rather than promising exact counting.

## Return
Supply the English prompt and a short explanation of the key design choices in the user's language, unless only a prompt was requested. Include a compact identity-anchor list when it will help subsequent sheets or edits. Do not claim an unseen reference matches a description.

Check the result conceptually for silhouette readability, consistency between garment layers, face visibility, crop, unwanted inherited attributes, and unnecessary detail.
